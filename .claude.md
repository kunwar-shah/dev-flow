# DevFlow Project Context

## Project Overview
DevFlow is an open-source command-line tool that provides a Laragon-style development environment optimized for WSL2 and Linux systems. It manages LAMP stack (Linux, Apache, MySQL, PHP) development environments with support for multiple PHP versions, SSL certificates, and automated site configuration.

## Problem Statement

Working with web development projects on WSL through `/mnt/c` mount points suffers from **severe I/O performance issues**, especially when running multiple AI coding tools like Claude Code. This project solves that by:
- Moving all development to native WSL filesystem (`~/websites`)
- Providing fast, native service management (no Docker overhead for main stack)
- Enabling easy site creation and management like Laragon on Windows
- Supporting unlimited sites with different PHP versions per site

**Target Users**: 
- Web developers using WSL for LAMP stack development
- Teams migrating from Laragon (Windows) to WSL
- Linux developers wanting simplified local development
- Developers running AI coding tools requiring fast I/O (Claude Code, Copilot)
- Open source contributors

## Key Design Decisions

1. **Native Services Over Docker**: LAMP stack runs natively for maximum performance; Docker only for special database versions
2. **JSON Configuration**: Structured data storage using `jq` for parsing and manipulation
3. **Site Registry**: Central `sites.json` tracking all managed sites with metadata
4. **Modular Architecture**: Subcommand-based CLI (like git) for intuitive usage
5. **Self-Signed CA**: Root certificate authority for trusted local SSL certificates
6. **Documentation-First**: Complete specifications before implementation to ensure quality
7. **Test-Driven Development**: Unit and integration tests alongside features (80%+ coverage)

## Core Principles

### 1. Performance First
- ALL operations must use native WSL filesystem (`~/` paths)
- NEVER use `/mnt/c/` paths for development files (9P protocol overhead)
- File I/O throughput target: > 500 MB/s
- Site creation must complete in < 30 seconds

### 2. Safety and Reliability
- ALWAYS validate Apache configurations with `apachectl configtest` before reload
- All operations must be atomic (all-or-nothing, rollback on error)
- Clear, actionable error messages: `Error: [what]. [why]. [how to fix].`
- Never leave the system in a partially configured state

### 3. User Experience
- Keep CLI output clean and informative
- Use color-coding: ✓ (green), ✗ (red), ⚠ (yellow), ℹ (blue)
- Show progress indicators for operations > 5 seconds
- Every command must have helpful `--help` documentation

## Development Guidelines

### When Working on Site Management
- Always use absolute paths (no relative paths)
- Validate site name format: `[a-z0-9.-]+\\.test`
- Check for existing sites before creation
- Ensure proper ownership: `user:www-data`
- Set correct permissions: directories 775, files 664

### When Working on SSL
- Root CA location: `~/.devflow/ssl/ca/`
- Site certificates: `~/.devflow/ssl/certs/{SITE_NAME}/`
- Private key permissions: 600 (critical for security)
- Always check if Root CA exists before creating site certs

### When Working with Databases
- Default encoding: UTF8MB4
- Generate random passwords (16+ characters)
- Store credentials in: `~/.devflow/db-credentials.txt` (600 permissions)
- Never log passwords to stdout

### When Working on Migration
- Use rsync for file transfer with progress
- Exclude: `node_modules/`, `vendor/`, `.git/`, `storage/logs/`
- Detect project type (Laravel, WordPress, etc.)
- Preserve file permissions and timestamps
- Show estimated time and size before migration

## Testing Requirements

### Unit Tests (BATS)
- Test coverage target: > 80%
- Test all critical functions
- Mock external dependencies (systemd, apache2ctl)
- Test both success and failure paths

### Example Test Structure
```bash
#!/usr/bin/env bats

setup() {
    # Run before each test
    export DEVFLOW_TEST_MODE=1
    export SITES_DIR="/tmp/devflow-test/sites"
}

teardown() {
    # Run after each test
    rm -rf "/tmp/devflow-test"
}

@test "site creation with valid input succeeds" {
    run create_site "test.test" "php8.2" "public"
    [ "$status" -eq 0 ]
    [ -d "$SITES_DIR/test.test/public" ]
}

@test "site creation with duplicate name fails" {
    create_site "test.test" "php8.2" "public"
    run create_site "test.test" "php8.2" "public"
    [ "$status" -eq 1 ]
    [[ "$output" =~ "already exists" ]]
}
```

## Known Issues and Workarounds

### Windows Defender in WSL
- After Windows updates, Defender exclusions may reset
- Always add `/mnt/c/projects` and `wsl.exe` to exclusions
- Recommend moving projects to native WSL filesystem

### systemd in WSL
- Must be enabled in `/etc/wsl.conf`
- Some users may need to enable it manually

### Apache on Port 80/443
- May conflict with Windows services
- Check with: `netstat -ano | findstr :80` (Windows)
